# NotchNotes Markdown 语法

只使用 NotchNotes MarkdownEngine 已实现的语法子集。用户原有内容即使超出这个子集，也要原样保留。

## 待办优先的笔记结构

每个新待办对应一篇完整 Note，不是共享待办列表中的一行。把复选框标题放在第一条有意义的内容中，方便 NotchNotes 生成易读的标签标题。用户提供了背景时，再写到标题下方。

```markdown
- [ ] 完成 NotchNotes Skill

需要先实现安全的本地 CLI，再由 Skill 调用。

- 验证原子写入
- 验证冲突检测
```

如果用户只给出简短标题，不要编造说明：

```markdown
- [ ] 交水费
```

Agent 只负责记录待办。除非用户明确要求修改内容，否则不要把 `[ ]` 改成 `[x]`。

## 支持的语法

````markdown
# 一级标题
## 二级标题

*斜体*
**粗体**
***粗斜体***
~~删除线~~
`行内代码`

> 引用

- 无序列表
1. 有序列表
- [ ] 未完成任务
- [x] 已完成任务

[链接文字](https://example.com)
[[Wiki 名称]]

```swift
print("code")
```

行内公式：$E=mc^2$

$$
\\int_0^1 x\\,dx
$$

---
````

外层示例用于描述语法；真正生成代码块时只使用三个反引号。语言名称可以包含字母、数字、`_`、`+`、`#`、`.` 和 `-`。

## 不要假定渲染支持

下列内容可以安全保存，但可能只显示为纯文本：

- YAML frontmatter
- GFM 表格
- 脚注
- Mermaid
- HTML 块
- 使用下划线的强调语法，例如 `_斜体_` 或 `__粗体__`

不要为了改变渲染效果而重写用户原有但尚未支持的语法。
